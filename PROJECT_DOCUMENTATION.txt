================================================================================
                        1. PROJECT OVERVIEW
================================================================================

The CUI Campus Bot is an intelligent question-answering system designed to 
provide accurate information about COMSATS University Islamabad (CUI) Vehari 
Campus. It uses Retrieval-Augmented Generation (RAG) architecture to combine:

- Document retrieval from a knowledge base (PDFs, DOCX, JSON files)
- AI-powered response generation using Perplexity LLM
- Local vector embeddings (BAAI BGE model) for semantic search
- Web interface built with Flask and modern HTML/CSS/JavaScript

KEY FEATURES:
- Free, unlimited local embeddings (no API quotas)
- Supports PDF, DOCX, and JSON document formats
- Real-time chat interface with conversation history
- Accurate, context-aware responses
- Restricts queries to CUI-related topics only
- Multi-page web interface (chat, timetable, feedback, login)

                    3. CORE MODULES AND THEIR FUNCTIONS
================================================================================

MODULE 1: app.py (Flask Web Application)
----------------------------------------
PURPOSE: Main web server and API handler

KEY FUNCTIONS:
- initialize_rag(): Initializes the RAG pipeline with vector store and LLM
- home(): Serves the landing page (index.html)
- chat_page(): Serves the chat interface (chat.html)
- timetable_page(): Serves timetable lookup page
- feedback_page(): Serves feedback form page
- login_page(): Serves admin login page
- chat() [POST /api/chat]: Handles chat queries, retrieves context, generates responses
- clear() [POST /api/clear]: Clears conversation history
- status() [GET /api/status]: Returns system status (online/offline)
- suggestions() [GET /api/suggestions]: Returns sample questions
- reload_pipeline() [POST /api/reload]: Reloads .env and RAG pipeline
- _strip_markdown(): Removes Markdown formatting from responses

DEPENDENCIES:
- Flask: Web framework
- flask_cors: Cross-Origin Resource Sharing support
- python-dotenv: Environment variable management
- rag_pipeline_free: RAG orchestration
- config: Configuration parameters


MODULE 2: config.py (Configuration Management)
----------------------------------------------
PURPOSE: Central configuration for all system parameters

KEY CONFIGURATIONS:
- PPLX_API_KEY: Perplexity API authentication key
- PPLX_MODEL: AI model selection (sonar, sonar-pro, etc.)
- PPLX_TEMPERATURE: Response creativity (0.3 = focused, deterministic)
- DATA_DIRECTORY: Path to knowledge base documents
- CHUNK_SIZE: Maximum characters per document chunk (1000)
- CHUNK_OVERLAP: Overlap between chunks for context (200)
- RETRIEVAL_TOP_K: Number of documents to retrieve (5)
- SYSTEM_PROMPT: Instructions for AI behavior and restrictions
- CHROMA_PERSIST_DIRECTORY: Vector database storage location
- SEARCH_TYPE: Similarity search algorithm

SYSTEM PROMPT DESIGN:
The SYSTEM_PROMPT restricts the bot to CUI-related topics only and ensures:
1. Accurate answers using only provided context
2. Rejection of non-CUI queries (programming, general knowledge)
3. Plain text formatting (no Markdown)
4. Concise, direct responses


MODULE 3: load_cui_data.py (Data Loader)
-----------------------------------------
PURPOSE: Load and process documents from various formats

KEY CLASSES:
- TextChunker: Splits text into manageable chunks
  * chunk_by_sentences(): Sentence-based splitting
  * chunk_by_paragraphs(): Paragraph-based splitting
  * chunk_qna_pairs(): Q&A format optimization
  
- CUIDataLoader: Main document loading orchestrator
  * load_json_qna(): Loads JSON Q&A files
  * load_pdf_timetable(): Loads PDF documents (timetables, policies)
  * load_docx_file(): Loads DOCX documents (admissions, scholarships)
  * load_all_data(): Scans directory and loads all supported files
  * get_chunking_stats(): Analyzes chunk size distribution

SUPPORTED FORMATS:
1. JSON: Question-answer pairs with metadata
2. PDF: PyPDF loader for timetables, policies, general info
3. DOCX: python-docx for Word documents (admissions, scholarships)

TEXT CHUNKING STRATEGY:
- RecursiveCharacterTextSplitter: Smart splitting at natural boundaries
- Separators: ["\n\n", "\n", ". ", " ", ""]
- Preserves context with overlap between chunks
- Maintains metadata (source, category, type)


MODULE 4: vector_store_free.py (Vector Database Manager)
---------------------------------------------------------
PURPOSE: Store and retrieve document embeddings using free local models

KEY FEATURES:
- BAAI BGE embeddings (bge-small-en-v1.5)
- ChromaDB persistent vector database
- No API keys required, unlimited usage
- CPU-based inference (no GPU needed)

KEY METHODS:
- __init__(): Initialize embeddings model and ChromaDB client
- add_documents(): Batch insert documents with embeddings
- similarity_search(): Find relevant documents by semantic similarity
- similarity_search_with_score(): Return documents with relevance scores
- get_retriever(): Create LangChain retriever interface
- delete_collection(): Reset vector database
- get_collection_stats(): Database statistics and health check

EMBEDDING MODEL DETAILS:
- Model: BAAI/bge-small-en-v1.5
- Dimensions: 384
- Max tokens: 512
- Normalized embeddings: Yes
- Device: CPU
- Size: ~130MB (downloaded on first run)

CHROMADB CONFIGURATION:
- Persistent storage: chroma_db/ directory
- Collection name: cui_campus_bot
- Distance metric: Cosine similarity


MODULE 5: perplexity_llm.py (LLM Integration)
----------------------------------------------
PURPOSE: Interface with Perplexity AI for response generation

KEY METHODS:
- __init__(): Initialize API client with key and model settings
- _call_api(): HTTP POST to Perplexity API with retry logic
- generate_response(): Simple prompt-response generation
- generate_response_with_context(): RAG-style generation with retrieved context
- generate_chat_response(): Conversational responses with history
- _extract_content(): Parse API response and extract text

PERPLEXITY API DETAILS:
- Endpoint: https://api.perplexity.ai/chat/completions
- Authentication: Bearer token
- Models available:
  * sonar (default): Fast, balanced
  * sonar-pro: Higher quality
  * sonar-reasoning: Step-by-step reasoning
  * sonar-deep-research: In-depth analysis
- Temperature: 0.3 (low = more focused/deterministic)
- Max retries: 5 with exponential backoff
- Timeout: 30 seconds

CONTEXT INJECTION:
The context from retrieved documents is formatted as:
"Based on the following information from CUI Vehari Campus database:
[Document 1 content]
---
[Document 2 content]
---
...
User Question: [query]
Provide an accurate answer using the information above."


MODULE 6: rag_pipeline_free.py (RAG Orchestrator)
--------------------------------------------------
PURPOSE: Coordinate the entire RAG pipeline from query to response

KEY METHODS:
- __init__(): Initialize data loader, vector store, and LLM
- _initialize_components(): Set up all pipeline components
- index_data(): Load and embed documents into vector store
- retrieve_context(): Query vector store for relevant documents
- generate_response(): Send context and query to LLM
- query(): Complete RAG workflow (retrieve + generate)
- get_pipeline_status(): System health and statistics

WORKFLOW:
1. User submits query
2. Query is embedded using BAAI BGE
3. Vector store returns top-K similar documents
4. Documents + query sent to Perplexity LLM
5. LLM generates response using context
6. Response is cleaned and returned to user

PARAMETERS:
- top_k: 5 documents retrieved per query
- chunk_size: 800 characters per document chunk
- chunk_overlap: 150 characters overlap
- search_type: "similarity" (cosine distance)


MODULE 7: initialize_db.py (Database Setup)
--------------------------------------------
PURPOSE: One-time setup script to index all documents

PROCESS:
1. Load all documents from cui_chatbot_data/ folder
2. Split documents into chunks
3. Generate embeddings using BAAI BGE
4. Store embeddings in ChromaDB
5. Verify with test retrieval

USAGE:
Run once before starting the chatbot:
$ python initialize_db.py

This creates the chroma_db/ directory with the indexed vector database.

                    6. API INTEGRATION DETAILS
================================================================================

PERPLEXITY AI API
-----------------
Base URL: https://api.perplexity.ai/chat/completions

AUTHENTICATION:
- Method: Bearer Token
- Header: Authorization: Bearer {PPLX_API_KEY}
- Key source: .env file or environment variable

REQUEST FORMAT:
{
  "model": "sonar",
  "messages": [
    {
      "role": "system",
      "content": "You are the official CUI Campus Bot..."
    },
    {
      "role": "user",
      "content": "Based on the following information..."
    }
  ],
  "temperature": 0.3
}

RESPONSE FORMAT:
{
  "id": "chat-xxxxx",
  "object": "chat.completion",
  "created": 1702812345,
  "model": "sonar",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "CUI Vehari Campus offers..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 250,
    "completion_tokens": 150,
    "total_tokens": 400
  }
}

ERROR HANDLING:
- 429 (Rate Limit): Exponential backoff retry
- 500-504 (Server Error): Retry up to 5 times
- Timeout: 30-second limit per request
- Network errors: Automatic retry with backoff

RATE LIMITING:
- Max: 60 requests per minute (configured in config.py)
- Delay: 0.5 seconds between calls
- Handled automatically by retry logic
